# OHQ-Slope

A local slope-stability workspace with a browser front end, a job-service back end, and independently usable scientific calculations. OpenHydroQual is a pinned dependency for the next hydrologic coupling stage.

## Current capability

- Configure a uniform infinite slope and pressure-head history at its failure plane.
- Run deterministic FS or seeded Monte Carlo calculations with independent uniform mechanical inputs.
- Inspect FS time series, 5–95% ensemble bands, sampled-time instability frequency, and recent jobs.
- Download the request, result, and calculation provenance as JSON.
- Track asynchronous progress, cancel jobs, and retain results across server restarts.

**Pressure histories are prescribed, not generated by OHQ.** The current app does not simulate rainfall infiltration, spatial slope geometry, seismic loading, deformation, or a live digital twin. Example inputs and uncertainty ranges are synthetic, not measurements or calibrated distributions. No paper materials are included.

## Run locally

Python 3.10 or newer is sufficient; the current app uses only its standard library. No front-end build or package installation is needed.

```sh
git clone --recurse-submodules https://github.com/behzadshakouri/OHQ-Slope.git
cd OHQ-Slope
python3 -m backend.server
```

Open **http://127.0.0.1:8765**. Stop with Ctrl+C. To choose another port:

```sh
python3 -m backend.server --port 8766
```

The server intentionally binds to loopback and accepts same-origin requests only. It is a local research tool; public hosting and authentication have not been implemented. Jobs are stored in ignored `results/jobs/` folders; pass `--jobs-dir /path/to/jobs` to select another location. A restart marks incomplete jobs as interrupted rather than silently resuming them.

## Run without the interface

```sh
python3 -m uncertainty.run models/prescribed_pressure_example.json --output results/example.json
```

The browser, API, and command-line runner use the same stability and uncertainty modules. See [the calculation specification](docs/calculation.md) and [API contract](docs/api.md).

## Verify

```sh
python3 -m unittest discover -s tests -v
node --check frontend/app.js
python3 scripts/check_dependency.py
```

Node is optional for the JavaScript syntax check. HTTP integration tests need permission to open local loopback sockets. Tests cover analytical force balances, pressure effects, uncertainty reproducibility and aggregation, HTTP input checks and result retrieval, cancellation, and restart handling. Browser visual inspection remains a separate check.

## OHQ dependency

```sh
git submodule update --init --recursive
python3 scripts/check_dependency.py
```

The dependency is a clean source baseline. It has not been built or validated for this slope application. Build instructions are in `external/OpenHydroQual/OHQLib/BUILD.md` and the engine's headless-runner documentation. No engine executable or generated kernel is included. The current calculation mode does not require building OHQ.

## Structure

| Directory | Purpose |
|---|---|
| `frontend/` | Buildless browser interface and SVG charts |
| `backend/` | Local HTTP API, persistent job records, single simulation worker |
| `stability/` | Uniform infinite-slope reference calculation |
| `uncertainty/` | Seeded ensemble calculation and CLI |
| `models/` | Synthetic runnable input specifications |
| `tests/` | Scientific and HTTP integration checks |
| `validation/` | Reserved for future hydrologic and external-model comparisons |
| `components/` | Reserved for verified custom OHQ JSON diagnostics |
| `config/` | Engine provenance |
| `external/OpenHydroQual/` | Pinned engine submodule |
| `results/` | Ignored generated outputs |
